Lesson 1

Find The Three Surfaces

Know whether a command is looking at intent, compiled OVN state, or local Open vSwitch state.

The Model

OVN configuration flows from north to south: CMS intent enters the OVN Northbound DB, ovn-northd translates it into the OVN Southbound DB, and ovn-controller programs local Open vSwitch.

1. Intent

ovn-nbctl reads and writes the logical network you asked OVN to create.

2. Compiled OVN

ovn-sbctl reads what ovn-northd produced for controllers.

3. Local OVS

ovs-vsctl and ovs-ofctl inspect what exists on the local virtual switch.

Sandbox Exercise

./ovn-setup.sh
ovn-nbctl show
ovn-sbctl show
ovs-vsctl show

Expected observation: ovn-nbctl show shows logical switches/router, ovn-sbctl show shows Southbound/chassis information, and ovs-vsctl show shows local OVS bridge/configuration state.

Retrieval Check

1. Which surface does ovn-nbctl show inspect?

2. Where should you look for state compiled by ovn-northd?

3. Which surface is closest to actual switching behavior on this sandbox chassis?

What To Read

Primary source: OVN sandbox tutorial. Reference: control-plane map.

Lesson 2

Trace One Packet

Describe what OVN would do to a packet before you look at OpenFlow.

The Model

ovn-trace does not send a real packet. It evaluates a hypothetical packet through the logical pipeline described in the Southbound database.

Start

sw0-port1
MAC 50:54:00:00:00:01
IP 192.168.0.2

Router

lr0
lrp0: 192.168.0.1
lrp1: 11.0.0.1

Finish

sw1-port1
MAC 50:54:00:00:00:03
IP 11.0.0.2

Sandbox Exercise

ovn-trace --minimal sw0 'inport == "sw0-port1" && eth.src == 50:54:00:00:00:01 && ip4.src == 192.168.0.2 && eth.dst == 00:00:00:00:ff:01 && ip4.dst == 11.0.0.2 && ip.ttl == 64'

Expected minimal trace:

ip.ttl--;
eth.src = 00:00:00:00:ff:02;
eth.dst = 50:54:00:00:00:03;
output("sw1-port1");

Retrieval Check

1. What does ovn-trace process?

2. What does ip.ttl-- tell you happened?

3. What does output("sw1-port1") identify?

What To Read

Primary source: OVN sandbox tutorial, section “Using ovn-trace.” Reference: ovn-trace cheatsheet.

Lesson 3

Read A Logical Flow

Read the Southbound rules that ovn-trace is walking through.

The Model

ovn-northd compiles Northbound intent into Southbound logical flows. A logical flow is a match-action rule with ordering:

table=0 (...), priority=50, match=(...), action=(next;)

Where?

table tells you the pipeline stage.

Which one?

priority decides among matching flows.

For what?

match describes packet fields.

Do what?

action tells OVN to continue, drop, rewrite, or output.

Sandbox Exercise

ovn-sbctl lflow-list sw0

ovn-sbctl lflow-list lr0

Pick one line and rewrite it as table, priority, match, and action.

What To Notice

On sw0, many table names start with ls_: logical switch. On lr0, many table names start with lr_: logical router.

Retrieval Check

1. In a logical flow, what does table identify?

2. If several flows match in one table, which priority wins?

3. Where does ovn-sbctl lflow-list read logical flows from?

What To Read

Primary source: ovn-logical-flows.7.rst. Reference: logical-flow reading guide.

Lesson 4

Find Local OpenFlow

Separate logical flows from the OpenFlow installed into local Open vSwitch.

The Model

ovn-controller runs on the chassis and translates relevant Southbound data into OpenFlow on br-int.

SB logical flows -> ovn-controller -> OpenFlow on br-int

Sandbox Exercise

ovn-sbctl lflow-list sw0

ovn-sbctl --ovs lflow-list sw0

ovs-ofctl dump-flows br-int

If --ovs prints only logical flows, try sw1 or lr0.

What To Notice

lflow-list

Logical names and OVN actions: inport, outport, next;, output;.

--ovs

Can show OpenFlow rows below corresponding logical flow rows.

dump-flows

Local OVS rules with table, metadata, reg, and actions.

Retrieval Check

1. Which daemon translates Southbound logical flows into local OpenFlow?

2. Which sandbox bridge receives the installed OpenFlow?

3. What does ovn-sbctl --ovs lflow-list add when local flows exist?

What To Read

Primary source: local OpenStack tutorial. Reference: local OVS/OpenFlow map.

Lesson 5

Add One ACL

Change Northbound intent and watch the change move into logical flows and trace behavior.

The Model

An ACL is Northbound intent: traffic matching this expression should get this verdict.

acl-add in NB DB
  -> ovn-northd compiles ACL logical flows in SB DB
  -> ovn-trace stops showing final output for the dropped packet
  -> ovn-controller can install changed OpenFlow locally

Sandbox Exercise

Add one ACL to sw0:

ovn-nbctl --wait=sb --may-exist acl-add sw0 from-lport 1001 'inport == "sw0-port1" && ip4.dst == 11.0.0.2' drop

Observe it:

ovn-nbctl acl-list sw0
ovn-sbctl lflow-list sw0
ovn-trace --ct new --minimal sw0 'inport == "sw0-port1" && eth.src == 50:54:00:00:00:01 && ip4.src == 192.168.0.2 && eth.dst == 00:00:00:00:ff:01 && ip4.dst == 11.0.0.2 && ip.ttl == 64'

Clean up exactly what you added:

ovn-nbctl --wait=sb acl-del sw0 from-lport 1001 'inport == "sw0-port1" && ip4.dst == 11.0.0.2'

What To Notice

NB intent

acl-list shows direction, priority, match, and verdict.

SB compile

lflow-list shows generated ACL logical flows.

Trace result

The dropped packet should no longer end with output("sw1-port1").

Retrieval Check

1. Where is the ACL first added?

2. Which daemon compiles the ACL into logical flows?

3. What is the trace clue that the drop worked?

What To Read

Primary source: ovn-nbctl ACL commands. Reference: ACL observation loop.

Lesson 6

Follow a Port Binding

Connect a logical port name to the local OVS interface that realizes it.

The Model

A local OVS interface realizes an OVN logical switch port when its external_ids:iface-id equals the logical port name.

NB Logical_Switch_Port: sw0-port1
  -> SB Port_Binding: logical_port=sw0-port1
  -> local OVS Interface p1: external_ids:iface-id=sw0-port1
  -> ovn-controller binds the Port_Binding to this chassis

Sandbox Exercise

ovn-nbctl lsp-list sw0
ovn-nbctl lsp-get-addresses sw0-port1
ovn-sbctl list port_binding sw0-port1
ovs-vsctl get Interface p1 external_ids:iface-id
ovs-vsctl list Interface p1
ovs-vsctl get Interface p2 external_ids:iface-id
ovn-sbctl list port_binding sw1-port1

What To Notice

Logical name

sw0-port1 is not a Linux device name. It is OVN's logical port name.

Local device

p1 claims sw0-port1 through iface-id.

Binding row

Port_Binding records how the logical port is realized.

Retrieval Check

1. What is the join key between the logical port and local interface?

2. Which OVS external ID names the logical port?

3. Which Southbound table represents the binding?

What To Read

Primary source: ovn-sb.5 Port_Binding table. Reference: port binding map.

Lesson 7

Read Router Ports

Predict the router's output port from the destination IP.

The Model

A logical router port is an L3 interface. Its networks value also tells OVN which destination IPs are directly connected behind that port.

lr0 has two router ports:

lrp0: 192.168.0.1/24, mac 00:00:00:00:ff:01
lrp1: 11.0.0.1/24,    mac 00:00:00:00:ff:02

Packet destination 11.0.0.2
  -> matches 11.0.0.0/24
  -> route out lrp1
  -> use lrp1 MAC as the new Ethernet source

Sandbox Exercise

ovn-nbctl lrp-list lr0
ovn-nbctl list logical_router_port lrp0
ovn-nbctl list logical_router_port lrp1
ovn-nbctl lr-route-list lr0
ovn-trace --minimal sw0 'inport == "sw0-port1" && eth.src == 50:54:00:00:00:01 && ip4.src == 192.168.0.2 && eth.dst == 00:00:00:00:ff:01 && ip4.dst == 11.0.0.2 && ip.ttl == 64'

What To Notice

Connected route

11.0.0.1/24 on lrp1 means 11.0.0.0/24 is reachable through lrp1.

No static route needed

lr-route-list lr0 can be empty and the trace still routes.

Trace evidence

The trace should show eth.src = 00:00:00:00:ff:02, which is lrp1's MAC.

Optional Deeper Look

ovn-sbctl lflow-list lr0

Look for logical router ingress flow names around lr_in_ip_routing and matches like ip4.dst == 11.0.0.0/24.

Retrieval Check

1. Which router port handles destination 11.0.0.2?

2. Which router port field creates directly connected routes?

3. Which field becomes the output router port's MAC?

What To Read

Primary source: ovn-nb.xml for Logical_Router_Port.networks, then ovn-logical-flows.7.rst. Reference: router port routing map.
